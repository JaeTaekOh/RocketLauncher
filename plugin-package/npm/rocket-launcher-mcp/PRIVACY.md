# Rocket Launcher: Privacy

Contact: https://github.com/JaeTaekOh/rocketlauncher/issues

- **What is read:** project files of the app you connect, such as the manifest, build files, Info.plist, string files, README, icons and screenshots. They are read only on the computer running the Rocket Launcher server (or, for the web app, only inside your browser).
- **Network:** (1) when you connect a public GitHub repository, the server reads it through `api.github.com` and `raw.githubusercontent.com`; (2) when a lessons API is configured (`lessonsApiUrl` in `js/config.js`, or the `ROCKETLAUNCHER_LESSONS_API` environment variable), shared review lessons use that URL (see below). No analytics, ads, accounts or other telemetry.
- **Stored:** analysis results, your choices and generated files are saved in `~/.rocketlauncher` on that computer (or in `ROCKETLAUNCHER_HOME`). Delete that folder to remove everything. The web app uses this browser’s localStorage instead.
- **Review lessons:** when you report a store review result, Rocket Launcher learns from it on this computer. A generalized lesson (store, guideline or ITMS code, short advice, counters) is saved in `~/.rocketlauncher/lessons.json`, with an anonymized copy in `lessons-export.json` for your own review. The lessons file never keeps the store’s original message, app names, emails or keys; the original message stays only in that project’s own folder. Delete those files to forget every lesson.
- **Shared review lessons:** to improve the checks for every user, when a lessons API is configured each real (non-demo) learned review result sends one anonymized record to that API. It contains **only** `store` (`apple` or `play`), `codes` (guideline numbers such as `5.1.1(v)`, `ITMS-#####` codes, or a Google Play policy id from Rocket Launcher’s fixed table), `advice_id` (a key of that fixed table) and `event` (`rejected`, or `passed` after a later approval). Example: `{"v":1,"event":"rejected","store":"apple","codes":["4.8"],"advice_id":"4.8"}`. The tool result shows the exact record (`lesson.shared`) when a send is attempted.
  - **Never sent:** the store’s message, app name, bundle or package id, project id, file paths, e-mail addresses, names, phone numbers, URLs, keys, review notes or any other free text. A Google Play policy name that could only be read from the message text is not shared at all.
  - **On the server:** one running count per store + codes + advice id (no rows per person or per app), plus the day it was last seen. IP addresses, if used at all, should be used only as a salted hash for a short rate limit and should expire automatically; request bodies should not be logged. A Worker template for this is in `workers/lessons/`.
  - **Reading the feed:** when the API is configured, Rocket Launcher downloads the combined counts (cached in `~/.rocketlauncher/shared-lessons.json` for 12 hours) and shows matching items as “From other reviews” reminders or warnings. Their titles and advice come only from Rocket Launcher’s own table; text from the server is ignored. They never become must-fix items.
  - When the lessons API URL is empty, nothing is sent or fetched and lessons stay on this device. The built-in demo never sends anything. If the API cannot be reached (5-second timeout), everything keeps working on your computer.
- **Not collected:** no tokens, passwords or store credentials are requested, and nothing is ever submitted to Google Play or the App Store by Rocket Launcher.
- **Your AI client:** the assistant you use (Grok Bot, Claude, Cursor, …) sees the tool results under its own privacy terms.
